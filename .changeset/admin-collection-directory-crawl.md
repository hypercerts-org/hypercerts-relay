Add a manual collection directory crawl to Administration. Operators can crawl one enabled, approved PDS source from the PDS sources page, or all enabled sources from the new Collection directory page, and see active crawls, repositories described, and whether each crawl finished, failed, or was already running. Each request is recorded in the audit log with the operator, time, source and result. To enable it, set `COLLECTIONDIR_CONTROL_URL` to the collection directory's private origin and `COLLECTIONDIR_CONTROL_TOKEN_FILE` to a file containing its `COLLECTIONS_ADMIN_TOKEN` (at least 32 bytes) on the Administration service; on Railway set `HC_COLLECTIONDIR_CONTROL_SECRET` instead of the file. Without these variables the action is disabled and nothing else changes. The collection directory's `POST /admin/pds/requestCrawl` now reports per host whether a crawl started or was already active, and `GET /admin/crawlStatus` additionally reports recently finished and failed crawls (`host_results`, kept in memory for up to 256 hosts) and `process_start`; existing fields are unchanged. Deploy the collection directory and Administration from the same release. Crawl results remain candidate DID/collection pairs, not an authoritative inventory.
